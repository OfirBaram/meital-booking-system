# אין הזמנה עצמית אונליין באתר

החלטה עסקית, 3 באוגוסט 2026. פניות לקביעת תור עוברות **בווטסאפ בלבד**.

`frontend/booking.html` ו-`frontend/booking.js` נשארים ב-repo כדי שאפשר יהיה
לשחזר את הזרימה, אבל **הם לא נפרסים**. עמוד שאינו מקושר אך כן נגיש עדיין נמצא,
משותף ומאונדקס — ולכן לא מספיק "לא לקשר אליו".

## מה נחסם ואיפה

| מקום | מה נעשה |
|---|---|
| `vite.config.js` | `booking.html` הוסר מ-`rollupOptions.input` — לא נבנה ולא נפרס |
| `frontend/public/sitemap.xml` | רשומת ה-URL הוסרה — גוגל לא מקבל הפניה אליו |
| `frontend/public/robots.txt` | `Disallow: /booking.html` ו-`/booking.js` |
| `frontend/public/sw.js` | הוסר מה-precache, ו-`CACHE` עלה ל-`meital-v3` |
| `frontend/sw.js` | אותו דבר, `CACHE` עלה ל-`meital-v8` |
| `frontend/my-booking.html` | כפתור "הזמיני שוב" מפנה עכשיו לווטסאפ |
| `frontend/admin.js` | תצוגה מקדימה של ערכת הנושא מפנה תמיד לדף הבית |

### למה ה-Service Worker קריטי כאן

`booking.html` היה ב-precache של שני ה-Service Workers. מכשיר שביקר באתר בעבר
שומר עותק מקומי, וה-SW מגיש אותו גם אחרי שהקובץ ירד מהשרת. הסרה מהרשימה לבדה
לא מספיקה — מספר גרסת ה-`CACHE` חייב לעלות, כי רק שינוי שלו מפעיל את מסלול
ה-activate שמפנה caches ישנים. שתי הגרסאות הועלו.

## מה **לא** נחסם, ובכוונה

- **`my-booking.html`** — פורטל ללקוחה שכבר יש לה תור: צפייה, ביטול ושינוי מועד.
  זו לא קביעת תור חדש, והלינק נשלח ב-SMS ללקוחות פעילות. הסרה שלו הייתה משאירה
  לקוחות אמיתיות בלי דרך לבטל.
- **כלי `book_appointment` בבוט הוואטסאפ** (`supabase/functions/_shared/bot-core.ts`)
  — הבוט עדיין יכול לקבוע תור בשיחת וואטסאפ. זה ערוץ הוואטסאפ, לא האתר.
  אם רוצים לחסום גם אותו, זו החלטה נפרדת שצריך לקבל במפורש.
- **פונקציות ה-Edge של ההזמנות** (`verify-and-book`, `get-slots`, `send-otp`) —
  נשארות פרוסות. הדשבורד והבוט משתמשים בהן. הן פשוט אינן נגישות יותר מהאתר.

## אם רוצים לשחזר

להחזיר את השורה `main: entry('booking.html')` ל-`vite.config.js`, את רשומת
ה-URL ל-sitemap, ולהסיר את שורות ה-Disallow. אין צורך לשחזר את ה-SW — קובץ
שנטען דרך הרשת נכנס ל-cache ממילא.
